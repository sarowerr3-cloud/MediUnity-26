1. Project Overview

MediUnity ( Medi-Unity ) is a comprehensive, cloud-ready healthcare management platform built for the Cumilla region of Bangladesh. It connects patients with doctors through a feature-rich web application that supports appointment booking, online payments, health tracking, community forums, medical records, prescriptions, and an administrative control panel.

1.1 Core Objectives

  • Patient Portal: Allow patients to browse doctors, book appointments (video/offline), pay online via aamarPay, manage health records, track vitals, participate in community forums, read medical articles, and maintain recovery journals.
  • Doctor Portal: Enable doctors to manage their profiles, schedules, appointments, prescriptions, queue boards, and communicate with patients via in-app messaging.
  • Admin Dashboard: Provide super-admins, moderators, and support staff with tools to manage doctors, patients, services, appointments, community posts, verify identities, view audit logs, and monitor revenue analytics.

8. Backend — Middleware

8.1 firebaseAuth.js (Global Optional Middleware)

Populates req.auth with user info. Supports dual authentication:

  1. Custom JWT (Patient) — Verified with JWT_SECRET, sets req.auth.userId
  2. Firebase ID Token — Verified against Google's public keys (RS256), validates audience and issuer for project Medi-Unity -cumilla

Also exports requireFirebaseAuth — guard middleware that blocks unauthenticated requests.

8.2 adminAuth.js

JWT-based admin authentication. Verifies token, checks role against valid roles (super-admin, moderator, support). Supports legacy role: "admin" tokens (mapped to super-admin). Attaches req.admin with adminId, email, role.

Exports requireRole(...roles) — higher-order middleware for role-specific route protection.

8.3 doctorAuth.js

JWT-based doctor authentication. Verifies doctor token and attaches req.doctor with full doctor object from database.

8.4 multer.js

General file upload middleware using Multer with disk storage. Configures upload directory and file naming with timestamps.

8.5 lockerMulter.js

Specialized Multer configuration for medical file locker uploads with appropriate file size limits and type restrictions.

9. Backend — Utilities

9.1 bmdcScraper.js — Automatic BMDC Verification

A sophisticated web scraper that verifies doctors against the Bangladesh Medical & Dental Council (BMDC) official portal (verify.bmdc.org.bd). The process:

  1. Session Init: GET request to BMDC portal, extract CSRF token, cookies, and CAPTCHA image URL
  2. CAPTCHA Solving: Download CAPTCHA image → preprocess with Jimp (resize 3x, greyscale, contrast, threshold) → OCR with Tesseract.js (PSM 8: single word mode)
  3. Form Submission: POST registration number + solved CAPTCHA to /regfind
  4. Result Parsing: Parse HTML response with Cheerio to extract registered name and status
  5. Fuzzy Name Matching: Compare input name vs BMDC registered name (normalized, stripped of "Dr." prefix)
  6. Auto-Retry: Up to 6 attempts on CAPTCHA solve failures

9.2 cloudinary.js

Cloudinary v2 integration for image/file upload and deletion. Auto-removes local temp files after upload. Supports organized folders: doctors, services, doctor_certificates, nid_cards, patient_avatars, medical_reports.

9.3 email.js

Nodemailer transporter for OTP delivery via Gmail SMTP. Falls back to console-simulated emails when EMAIL_USER/EMAIL_PASS are not configured. Sends beautifully formatted HTML emails for account verification and password reset.

10. Authentication System

10.1 Dual Authentication Architecture

Two parallel authentication systems coexist:
1. Firebase Authentication — Google SSO, email/password via Firebase
2. Custom JWT Authentication — Email/phone + password signup with OTP verification via backend

10.2 Patient Authentication Flow

Option A: Firebase (Google SSO)

  1. Patient clicks "Sign in with Google" → Firebase signInWithPopup
  2. Firebase returns ID token → stored in React state
  3. All API requests include Authorization: Bearer <firebase_id_token>
  4. Backend firebaseAuth middleware verifies token against Google's public keys
  5. Sets req.auth.userId = payload.sub (Firebase UID)

Option B: Custom Credentials (Email/Phone + Password)

  1. Patient signs up with name, email, phone, password → POST /api/patients/signup
  2. Server creates profile, generates 6-digit OTP, sends via email (Nodemailer)
  3. Patient verifies OTP → POST /api/patients/verify-otp
  4. Server issues JWT token (7-day expiry) → stored in localStorage
  5. Subsequent logins via POST /api/patients/login
  6. Backend firebaseAuth middleware checks custom JWT first, then Firebase token

10.3 Doctor Authentication

  1. Doctor signs up with name, email, password, BMDC number → POST /api/doctors/signup
  2. Backend runs automatic BMDC verification (scraper + CAPTCHA solver)
  3. If verified → account created with isVerified: true
  4. If scraper fails → account queued for manual admin review (verificationStatus: "Pending")
  5. Doctor login via POST /api/doctors/login → JWT token issued
  6. Password stored as bcrypt hash (with plain-text fallback upgrade on login)

10.4 Admin Authentication

  1. Admin login via POST /api/admin/login
  2. Credentials verified against Admin collection (bcrypt hashed passwords)
  3. IP security: unknown IPs trigger security alerts, added to knownIps
  4. JWT with {adminId, email, role} issued (7-day expiry)
  5. All admin actions logged to AuditLog collection
  6. Frontend enforces 15-minute inactivity auto-logout

11. Payment Integration (aamarPay)

11.1 Payment Gateway

aamarPay is a Bangladeshi payment gateway supporting BDT transactions. The integration supports:

  • Doctor Appointments: Online payment via /api/appointments
  • Service Appointments: Online payment via /api/service-appointments
  • Cash Payments: Appointments can be booked as "Cash" (no online payment)
  • Free Appointments: ₹0 fee appointments auto-confirmed

11.2 Payment Flow

  1. Frontend sends appointment creation request with paymentMethod: "Online"
  2. Backend generates transaction ID (DOC-{timestamp} or SVC-{timestamp})
  3. Backend sends JSON POST to aamarPay API (jsonpost.php)
  4. aamarPay returns payment_url → Frontend redirects user to payment page
  5. After payment, aamarPay sends IPN callback to /api/appointments/aamarpay/callback
  6. Backend verifies pay_status === "Successful", updates appointment status to Confirmed
  7. User redirected to /appointment/success?session_id=...
